# Sephiria ModMaker

手動でインストールする場合は、Releaseの **SephiriaModMaker-バージョン.zipだけ** をダウンロードしてください。**update.jsonを別途ダウンロードしたり、インストール先に置いたりする必要はありません。** 自動更新がバージョンと検証情報を読むためのファイルです。エディター内で更新を選べばZIPのダウンロードも自動で行います。

- READMEと更新履歴はGitHubリポジトリで確認できます。ReleaseのZIPには含まれません。
- 起動するたびに更新を確認します。新しいバージョンがあると更新画面が開き、閉じても上部の通知から後で更新できます。自動確認が無効の場合やスキップしたバージョンでは自動画面を表示しません。

## アセットライブラリの使い方

バニラ事典からアセットライブラリを開き、ゲームアセットを読み込みます。初回作成には時間がかかりますが、ゲームの起動は不要です。名前・種類・元ファイルで検索し、画像・フレームアニメーション・音声を確認できます。

Modを保存してから画像・動作の参照ボタンで選ぶと、`Assets/Library`に取り込まれます。PNGの横にある`.sprite.json`は基準点とゲーム内サイズを保持するため、一緒に保管してください。PNG・GIF・フレームフォルダーをファイルから選ぶこともできます。音声はゲームイベントへの参照として保存し、WAVには抽出しません。アニメーションの取り込みで攻撃判定・イベント・AIはコピーされません。

## ステータスを行ごとに共有

常時ステータス表で共有したい行の**パーティ共有**を有効にします。**すべての効果を他のパーティメンバーと共有**が有効な間は行ごとの選択を使いませんが、選択値は保持します。共有するステータスはゲーム内ツールチップの行末に表示されます。

## インストール

1. [Releases](https://github.com/Xetsumei/Sephiria-ModMaker/releases)からzipを落として好きなフォルダに展開します。
2. [.NET Desktop Runtime 10](https://dotnet.microsoft.com/download/dotnet/10.0)をインストールします。
3. `ModMakerEditor.exe` を起動します。

ゲームフォルダは初回起動時に自動で探します。見つからなければ `Preferences (設定)` で直接指定してください。

エディタを起動しただけではゲームを変更しません。`ゲームに導入` を押したときに、インストール済みの版と同梱ランタイムを確認して適用します。起動時に自動でインストールさせたい場合は設定で選べます。
状態確認と再インストールは `Preferences (設定)` の `ModMaker Runtime` から行います。

別途ローダーは不要です。ゲーム内蔵のアドオンローダーがそのまま読みます。

## クイックスタート

1. `新規MOD` で空のフォルダを選びます。`mod.json` と `Assets/` ができます。
2. `MOD情報` タブでMod ID・表示名・作者を書きます。`新規コンテンツの開始ID` は新しいコンテンツの採番の基準です。作られたアイテム・武器・魔法の番号は、並べ替えても削除しても維持されます。
3. `アイテム` タブで `追加` を押します。内部名・種類・レアリティを選び、表示テキストとアイコンPNG(16×16から32×32のドット絵を推奨)を入れます。
4. `常時ステータス効果` でステータスを付けます。ステータス欄を押すとID・名前・説明のどれからでも検索できます。レベル別の値はカンマ区切りで、**(最大レベル + 1)個**必要です。
5. `検証` を押してから `ゲームに導入`、そして `F5` でゲームを起動します。新しいランを始めると報酬やショップに出ます。

> アドオンはタイトル画面ではなくゲームセッションに入るときに読み込まれます。ロビーかランまで入る必要があります。

すぐ確認したいときは `AddOns\ModMakerRuntime\config.json` に `"testGiveItems": true` を入れてください。ランに入るときカスタムアイテムが1個ずつ支給されます。
配布する前には `false` に戻してください。`配布用ファイルを作成` は自動で切ってくれます。

## アイテム

### 発動効果

`トリガー + 条件 + 動作` をカードのように積みます。よく使う組み合わせはテンプレートから一度に入ります。

* **トリガー36種:** 敵撃破 · 被弾 · 命中 · 空振り · 回避 · ドッジ · パリィ · カウンター · ガード成功/破壊 · 復活 · バフ/デバフ獲得・消滅 · 戦闘開始/終了 · ポーション · 箱・壺の破壊 · MP使用 · ゴールド獲得 · ステージ入場 · ゲームクリア · N秒ごと · 初回取得時1回 · HP/MP回復 · HP/MPが一定量減るたび・回復するたび · HP/MPが何%を上下に跨いだとき
* **動作26種:** HP・MP回復(%・固定) · 自傷 · MP消費 · シールド · 最大HP/MP増加 · ゴールド支給・消費 · アイテム支給・削除・強化 · ランダムアイテム · リロールダイス · 一時ステータス · 永続ステータス(ラン終了まで) · バフ付与・解除 · 一時無敵 · 硬直耐性 · 弾の発射 · 画面にテキスト表示
* **アイテム強化** は選んだアイテムに値の回数だけエンチャントをかけます(負の値ならその分解除)。マスではなくアイテムに付くので動かしてもついていき、ゲームのエンチャントと同じくアーティファクトにだけ最大レベルまでかかります。
* **弾の発射** はどの武器の投射物を借りるかを選び、ダメージ・属性・硬直・貫通回数を決めます。貫通は1なら最初に当たった一体で止まり、0なら寿命が尽きるまで飛び続けます。空欄なら借りた投射物の元の値を使います。
* **打撃の種類** は基本攻撃・ダッシュ攻撃・特殊攻撃・専用打撃・モンスター打撃の五つです。前の四つは武器から、最後の一つはモンスターから借ります。
* **モンスター打撃** はモンスターを選び、そのモンスターの打撃欄をもう一度選びます。モンスターも攻撃を武器と同じ打撃データで持っているので、そのまま出ます。貸せる打撃があるモンスターだけが一覧に出て、二つの欄を両方埋めないと発射されません。一覧はランタイムを入れた状態でゲームに一度入ると埋まります。
* **条件:** 発動確率(レベル別) · 再発動クールダウン · HP/MP割合 · 戦闘中のみ

> 持続時間が確実に切れる必要がある効果は `一時ステータス付与` ではなく `バフ付与` を使ってください。ゲーム本来のバフシステムを通るので、アイコン・残り時間・スタックがUIに出ます。

値が積み上がるアーティファクトもフォームだけで作れます。

* バフタブの `永続` を入れると時間が経っても消えません。
* `バフ付与` の `アイテムを失ったら一緒に解除` は永続バフでは必ず入れてください。切ると拾って捨てるのを繰り返して無限に積めます。
* `一時ステータス付与` の `最大累積` で「命中するたび1、最大50まで」をそのまま書けます。
* `永続ステータス付与` の `累積値表示` と効果行の `クールダウン表示` を入れると画面アイコンで見せます。表示用のバフはランタイムが勝手に作ります。

### 発動制約

アーティファクトが特定の状況でだけ効くよう制限します。ゲーム本来の制約は10種だけですが、`★ 自分で作る` を選べば条件を行単位で積めます。**すべての行を同時に満たしたとき**にオンになります。

| 条件 | 見られるもの |
|---|---|
| インベントリ内の位置 | 内側 · 縁 · 最上段/最下段 · 左端/右端 · 両端の列 · 角 |
| 指定の行 / 列 | 上からN番目の行、左からN番目の列 |
| 隣接マス · 周囲マス詳細 | 上下左右・斜め・周囲8マス × アーティファクト / 発動型 / 魔導書 / 仲間 / 石板 / ポーション / 空きマス / 何かのアイテム / 特定コンボ / 特定アイテム / 名前に文字を含むアイテム |
| インベントリ全体 | 上と同じ対象をN個以上持っているとき |
| HP · MP · 所持金 | 満タン · 満タンでない · N%以下 · N%以上 |
| 自分のステータス値 | 指定したステータスが一定以上・以下のとき |
| かかっているバフ | バフ・デバフどれでも / バフのみ / デバフのみ |
| 階 · 戦闘中 · このアーティファクトのレベル | そのまま |

各行には `反転`(…でないとき)と `すべて`(指定したマスが全部合致すること)を付けられます。
`説明文の自動作成` を押すと今の条件に合う文章がテキストタブの `発動条件` 欄に入ります。ツールチップにそのまま出る行で、手直しもできます。

`制約条件を無視させない` を入れると、制約解除の石板や刻印がこのアーティファクトには通りません。

> HP・MP・戦闘状態の条件はアイテムを持っている間しか判定できないため、置く場所を光らせるプレビューには反映されません。ゲーム本来の `HPが満タンのとき` 制約も同じです。

ゲームは本来インベントリが変わったときにしか制約を問い直しません。そのためHPやステータスのように戦闘中に変わる条件を持つアーティファクトだけ、ランタイムが0.25秒ごとに見て、答えが変わったときにその一つだけを更新します。`config.json` の `watchDynamicCriteria` で切れます。

### 出現条件

発動制約と同じ条件表で、アイテムが報酬やショップに出るかを決めます。インベントリに入る前に問う条件なので、位置に関する種類は外れます。
`武器1本の制限` をかけると、その武器を持っているときだけ出現し、ツールチップに専用表示が付きます。

### 外見装飾

ゲームの絶対の指輪が武器の柄に光をまとわせ、アグマ投影剣が背後に翼を浮かべるのと同じ枠です。

* 付ける場所はプレイヤーの体(ジャンプで一緒に浮きます) · 立ち位置(地面に残ります) · 武器の柄 · 武器の刃です。
* `追従` を遅れて付いてくる設定にすると、翼やマントのように引きずられます。
* ずらし(1は16ピクセルです) · 大きさ · 前後の順序 · 色調 · 最低強化レベル · 向きに合わせた反転を決めます。
* 発動制約をかけてあれば、条件を満たしている間だけ見せることもできます。

画像欄はPNG1枚かフォルダを受け取ります。フォルダなら名前順にフレームが回ります。GIFを選ぶとエディタがPNGフォルダに展開します。

> 見た目だけの飾りです。判定やダメージとは関係ありません。

### 画面効果

条件を満たしている間、自分の画面にかかる効果です。ゲームの青いリングと同じ枠です。

`画像の重ね` · `画面の色付け` · `周縁を暗く` · `彩度` · `白黒` · `明度` · `コントラスト` · `色相回転` · `色反転` · `画面振動` · `ズーム` · `グリッチ` · `画面歪み` · `暗転` · `青いリング効果`

位置(全体・両脇・上・下)、強さ、フェードイン・アウト、繰り返し間隔、呼吸のような点滅を行ごとに決めます。パーティメンバーと分け合うこともできます。

### ステータス変換

あるステータスの超過分を別のステータスに回します。ベルトの鎌がクリティカル率100%の超過分を処刑率に回すのと同じ方式で、どのステータスからどのステータスへでもかけられます。

### ステータス占有

あるステータスを縛っておき、その代償に別のステータスを上げます。渇望の宝珠がMPを占有して魔法ダメージを上げるのと同じ枠です。

MPを占有するとゲームの占有MPをそのまま使うので紫のバーで出ます。それ以外のステータスはその分引くだけです。
与える値はレベル別にカンマ区切りで書けて、上限も決められます。ツールチップの説明行は渇望の宝珠と同じ語順でランタイムが自動で付けるので、手で書く必要はありません。

> ゲームのステータスキー300余りのうち、呼び名が付いているのは半分だけです。名前のないステータスを占有するとツールチップにキーがそのまま出るので、`占有ステータス名` 欄に呼び名を直接書いてください。

### 石板グリッド

7×7のグリッドで**左クリック +1 / 右クリック −1 / 中クリックで空に**して埋めます。
1マスにレベルと一緒に `制約解除`(青)と `レベル反転`(紫)を重ねてかけられます。重ねるとゲームはレベルを全部足したあとに反転を適用します。
ゲームが表現できないマス(直線4マス超、斜め2マス以上)はロックされています。`CHECKERBOARD` のような特殊ルールは `高度 (テキスト)` タブで書きます。

### 結束アーティファクト

`結束アーティファクトとして生成` のチェックで決めます。コンボを2つ選んだだけでは結束になりません。ゲームにも、結束ではないのにコンボを2つ持つアイテムが15個あります。
レアリティは結束と関係なく選べます。結束は等級を置き換えるものではなく、その上に足される印です。チェックするとバニラの慣例に従って `レア` が初期値で入ります。

## 武器

武器は既存武器の**派生としてのみ**作ります。挙動とモーションはテンプレート武器のものをそのまま使い、スプライト・数値・名前だけを変えます。

> 武器リスト・打撃数・専用打撃はゲームが作る情報です。ランタイムを入れた状態で一度ランに入らないと武器タブの欄が埋まりません。

* **テンプレート武器** は複製元、**親武器** はこの武器に強化される武器です。親が1段ならこの武器は2段になります。直接入力するとき `0` は空欄ではなく剣と盾の1段なので、空にするなら `-1` と書いてください。
* **打撃数値** は1打が1行で、行数はテンプレートが決めます。基本欄は倍率・属性・硬直・ノックバックで、`高度` にヒットストップ・前進・MPあたり追加ダメージ・エイム補正・打撃タグ・ダメージ式があります。空欄はテンプレートの値をそのまま使います。
* **誰を殴るか** で対象(敵・味方)を選び、ダメージを回復に変えることもできます。回復倍率でどれだけ回復するかを決めます。
* **投射物のスプライト** はその打撃が撃つものの絵を差し替えます。基準点と回転も一緒に決めます。
* **投射物の挙動** は速度倍率・寿命・貫通・大きさ倍率・誘導と誘導力・壁に当たったときの処理・跳ね返り回数です。
* **複数発射** で連射回数と連射間隔(ms)を与えます。
* **命中時にかけるバフ・デバフ** で、殴られた側か殴った側にバフをかけます。
* **属性** は物理・炎・氷・雷だけを選びます。それ以外の属性は掛ける属性ステータスがなく、ダメージが大きく落ちます。
* **武器種専用の打撃** が別に現れる武器があります。火の棍棒のように基本コンボを一切使わない武器です。基本コンボを直したのにゲーム内で変わらないなら、こちらを見てください。
* **クロスボウ諸元** は装填数・マガジン数・リロード・発射間隔です。クロスボウの系譜はクロスボウ同士でしか繋げません。
* **スプライト** は日誌・金床用の画像と外見スプライト(本体・補助・刃の重ね・頭)です。テンプレートにない部位はロックされます。基準点は空欄ならテンプレートのものを引き継ぐので、ほとんど触る必要はありません。

`テンプレート武器の初期値に戻す` でいつでも最初に戻せます。

## 魔法

既存魔法を複製して、名前・アイコン・レベル別の消費MP・クールダウン・使用回数・詠唱速度・系統・ラベル色を変えます。作った魔法は `魔導書` アイテムの `使用する魔法` で選ぶとゲームに出ます。

* **テンプレートの挙動そのまま** は既存魔法の挙動を使います。何が飛んでどう爆ぜるかは複製元の魔法が担います。
* **バフ魔法** は挙動をこのツールが作ります。詠唱するとHPを回復させ、指定したバフをかけます。近くのパーティメンバー全員にかけることもできます。MP消費とMP不足時の詠唱阻止はゲームがやってくれます。

> 継続回復はバフ側で作ります。ゲームの `HP_REGEN` は10秒あたりの回復量なので、5秒間に毎秒4回復させるなら持続時間5秒に `HP_REGEN 40` です。

## キャラクター (コスチューム)

既存コスチュームを複製して、能力値・初期アイテム・初期武器を変えます。作ったキャラクターは選択画面に正式に出ます。状態遷移とヒットボックスは複製元のものを使います。

---

## 仲間

仲間アーティファクトはユニットを召喚したあと持ち主の陣営に変え、持ち主をリーダーにします。陣営を変える処理はゲームがすでにやっているので、**敵モンスターもそのまま仲間になります。**

* **ゲームのモンスターをそのまま使うなら** アイテム種類を `同行の証` にして `召喚するユニット` で選びます。選べるのは `バニラ事典` の `ユニット` タブで `仲間にできる` が付いているものです。
* **新しい仲間を描くなら** `仲間` タブでバニラモンスターを複製し、スプライト・名前・HP・移動速度・体の大きさを変えます。作ったユニットもアーティファクトの `召喚するユニット` 欄から選べます。

攻撃力・復活時間・レベル別の成長値はユニットではなくアーティファクト側が持ちます。

> ボスとミニボスは使えません。専用AIがフェーズと演出を握っています。
> 攻撃方法と動き(AI)は新しく作れません。`複製するモンスター` はつまり「どう戦うか」を選ぶ欄でもあります。
> `体の大きさ` は召喚する場所を探すときに使う値です。絵だけ大きくしてこれを直さないと、壁に埋まったまま召喚されます。

## 敵

* **敵の調整** はバニラの敵とボスのHP倍率・ダメージ増加・移動速度・大きさ・パターン間隔・ステータスを変えます。対象はAIクラス名・プレハブ名・ユニットIDのどれでも書け、空欄ならその種類全体にかかります。空欄の項目は元のままです。値は敵が出るたびにホスト側で一度適用されます。
* **敵の追加** はバニラモンスターを複製してスプライト・名前・数値だけ変えた新しい敵を作り、階に置きます。差し替えは階の構成と数を触らないので一番安全で、ウェーブに足すとその分難易度が上がります。

パターンを新しく作ったり順番を変えたりするのはボスごとにコードが違うためフォームには収まりません。カスタムスクリプトで行ってください。スクリプトプロジェクトを作ると `SampleEnemy.cs` の例が一緒にできます。

## そのほかのタブ

* **才能** はレベルごとのステータスとレベル5/10/20の特典です。枠を空にするとバニラ才能の枠を借りて代表色で染め、特典アイコンを空にすると同じ段階の絵を借ります。
* **コンボ** は新しいアイテムカテゴリと個数別のセット効果です。
* **奇跡** は階を移動するときに選ぶ祝福です。選んだあとランが終わるまでステータスが維持されます。
* **運命の刻印** は村の木でサファイアを払って買う解放枠です。ここで作った枠は前の刻印の後ろに繋がり、アイテムタブで `解放が必要` を入れたアイテムを解放します。サファイア価格をカンマ区切りで書くと複数回買える枠になります。
* **キーワード** は説明に埋める `<tag=…>` の名前です。色とアイコンを付ければバニラのキーワードと同じ扱いになります。ゲームにすでにある名前と重なるとスキップされます。
* **ステータス** はModが数える新しいステータス名です。ゲームのステータスは名札の付いた数字の辞書一つなので、名前を登録しておけばバニラのステータスと同じように積まれて読まれます。ただしゲームが勝手に使うことはないので、発動制約(`自分のステータス値`)やステータス変換で繋いでください。

## バニラを直す

* **アイテムパッチ** は既存アイテムの価格・サファイア価格・レアリティ・カテゴリ・最大レベル・ステータスを変え、アイコン・名前・フレーバーテキストも差し替えます。
* **コンボパッチ** はバニラコンボの段階表を書き直します。`バニラの値を読み込む` で現在の表を埋めてそこから直してください。バニラは2・3・4・5・6個の段階だけですが個数制限はないので、20個の段階も入れられます。1行でも書けばバニラの表を丸ごと置き換えます。
* **コスチュームパッチ** は既存キャラの能力値・初期アイテム・初期武器を調整します。

直した内容はゲームを起動している間は維持され、戻すにはゲームを再起動します。

## MOD専用機能

コンテンツ1つではなく、**MOD全体がバニラにかける設定**です。左の一覧の `MOD情報` のすぐ下、`MOD専用機能` のまとまりにあります。

* **バニラBAN** はチェックしたバニラコンテンツをゲームのダミーデータのようにします。データはゲームに残るので、すでに持っているものやセーブは壊れず、プレイヤーが新たに出会えなくなるだけです。検索と `BANしたものだけ表示` で探し、複数行を選んでまとめてBAN・解除できます。
  * **アイテム** 解放されないため、報酬・商店・神秘の壺・奇跡・図鑑・プリセットに出ません。効果で直接渡すものや開始アイテムに書いたものはそのまま支給されます。
  * **武器** 金床・訓練場の強化候補、図鑑の系譜、開始武器のランダム候補から外れます。1段階の基本武器は武器種を選んだ瞬間に持たされるため、開始武器としてはそのまま出ます。
  * **コスチューム** キャラクター選択画面に出ず、解放されません。着ていた人は次に入るときに基本キャラクターに変わります(進行中のランはそのまま)。
  * **奇跡** 奇跡の選択肢と図鑑から外れます。ある段階に残る奇跡が3つ未満になると、その段階にはBANがかかりません。
  * **才能** 才能画面とプリセットから外れ、ポイントを振れません。すでに振ったポイントはセーブに残り、BANを解除すると戻ります。
* 複数のMODがBANを指定するとすべて合わせて適用されます。一覧は `バニラ事典` と同じ資料を使うため、空ならランタイムを導入した状態でゲームを一度起動してください。

## バニラ事典

ゲームに入って照合しなくて済むよう、ランタイムが読み取った値を6つのタブで見せます。検索欄は6タブに同時にかかります。

* **アイテム** 種類・レアリティ・価格・最大レベル・コンボ・制約・ステータス
* **武器** 武器系統・強化段階・親武器・打撃数・使うスプライト枠・本体スプライトの基準点・専用打撃枠・クロスボウ諸元
* **才能** 最大レベル・レベルごとのステータス・レベル5/10/20の特典
* **コンボ** 果物名・このコンボを使うバニラアイテム数・段階別のセット効果・`使えるか` どうか
* **バフ** 持続時間・最大スタック・付与するステータス・実装クラス
* **ユニット** 陣営・性向・AI・`仲間にできる` かどうか

一覧から一つ選んで `選択アイテムのパッチを作成` を押すと、その場でアイテムパッチができます。

> コンボの `使える` が切れているものは、ゲームに登録だけされていてどのアイテムも使わないカテゴリです(例: `PARTY`)。選んでも何も起きないので、アイテムタブの選択肢から自動で外れます。

## エディタの便利機能

* **リストの検索** 左のリストにはそれぞれ検索欄があります。表示名でも内部名でも探せて、韓国語の名前は**初声だけでも**引っかかります(ㄱㅁㅅ で 고물상)。完成した文字と初声を混ぜても構いません。リストに出ていない他言語の名前でも探せます。絞り込むときも行を抜かずに隠すだけなので並び順が崩れず、フォルダは中に該当する行があるときだけ残ります。Esc で消し、↓ と Enter でリストへ降ります。
* **リストの整理** 左のリストのどこでも右クリックすると区切り線とフォルダを入れられます。フォルダの後ろにあるだけでは入らず、フォルダ名の下かフォルダの中に置いたものだけが入ります。左端まで引っ張ると外に出ます。名前は `F2` で直します。エディタ画面だけの印なのでゲームには影響せず、`mod.json` には置いた位置だけが記録されます。
* **ドラッグで並べ替え** は左のリスト全部でできます。複数行を選んでまとめて動かせて、複製ボタンもあります。
* **他のModから取り込み** は他のModの内容を今のModにコピーします。元のModは変わりません。`mod.json` のあるフォルダを開けば発動効果までそのまま移り、ゲームにインストール済みのModを読むと数値・テキスト・構成だけが移ります。C#コードで書かれた挙動は移りません。2つ目の方式は、そのModとランタイムを一緒に入れた状態でゲームを一度起動しないとリストができません。
* **検証** は保存を止めるエラーと参考用の警告を分けて知らせます。エラーは内部名の規則違反・重複、レベル別の値の個数不一致、存在しないステータスIDです。警告はアイコン欠落、効果のないアイテム、ゲームにない `<tag=…>`、低すぎる開始IDなどです。
* **多言語** エディタ画面は `Preferences (設定)` で変えます。保存すると自動で再起動します。ボタン名に `Preferences` が常に残っているので、読めない言語に変えても戻ってこられます。Mod内のテキストは `MOD情報` タブで基本言語と追加の翻訳言語を選びます。

### ゲーム内の `ModMaker情報` 画面

オプション画面の `ModMaker情報` を押すと、ランタイムのバージョンとインストール済みModの一覧が出ます。

* Modの行を押すとオン・オフを切り替えられます。`[ 変更を適用 ]` を押すと保存してゲームが終了し、次の起動から反映されます。ラン中はセーブが壊れるため出ません。
* `アイテム説明にMod名を表示` を入れると、すべてのカスタムアイテムの説明の一番下に `#Mod名` の1行が付きます。こちらはすぐ反映され、切っても元の文章はそのまま残ります。
* 同じModを使う人同士にだけ部屋が見えるロックは常にオンで、切ることはできません。下の[マルチプレイ](#マルチプレイ)を見てください。

## カスタム C# スクリプト

フォームで表せない動作は自分で書きます。配管はModMakerがやるので、クラスを一つ書くだけです。

1. `詳細カスタムスクリプト` を開いて `スクリプトプロジェクトを開く` を押します。Modフォルダに `Scripts/` プロジェクトができます。ゲームDLL参照・ターゲットフレームワーク・出力先はすべて設定済みです。
2. クラスを書きます。

   ```csharp
   public class BloodPact : ModMakerCharm
   {
       public override void OnCharmEffectRefreshed()
       {
           base.OnCharmEffectRefreshed();
           Log($"レベル {Level}");
       }
   }
   ```
3. `スクリプトをビルド` を押すとModフォルダに `Scripts.dll` ができます。
4. `カスタムスクリプト` 欄にクラス名を書きます。

| ベースクラス | 使う場所 | 継承するゲームクラス |
|---|---|---|
| `ModMakerCharm` | アイテム | `Charm_StatusInstance` |
| `ModMakerPerk` | 才能の特典 | `PassiveObject` |
| `ModMakerWeaponAddon` | 武器 | `WeaponAddon` |
| `ModMakerEnemy` | 敵 | `MonoBehaviour` |

常時ステータス・テキスト・アイコン・ID・翻訳はフォームで設定した値がそのまま使われ、挙動だけをコードが担います。

直接ダメージを与えるときは `DealDamage` を使ってください。

```csharp
DealDamage(target, 30f, EDamageElementalType.Fire);
```

ゲームは与えたダメージを `DamageInstance.id` でまとめてリザルト画面のダメージ統計に出しますが、知らない文字列だと `名前 (Unknown)` のまま残ります。`DealDamage` はModMakerがコンテンツごとに用意したIDを使うので、そのコンテンツの名前とアイコンで集計されます。
効果ごとに枠を分けたいときは `ModMakerDamage.Register("MyMod_Echo", "エコー")` でIDを登録し、`ModMakerDamage.Deal(...)` に渡してください。

> * `スクリプトをビルド` 一回でそのModのスクリプトが全部 `Scripts.dll` 一つにまとまります。押すたびにゲームDLL参照を最新に合わせ、フォームに書いたクラス名が実際にあるかも確認します。
> * ビルドには .NET SDK が必要です。
> * Mirrorの `SyncVar` はウィービングが要るためModからは追加できません。状態は普通のフィールドに置いてください。
> * 例外が出ても残りのコンテンツは生き残りますが、`Player.log` を確認してください。
> * **スクリプト入りのModを配布すると、受け取った人が任意のコードを実行することになります。** 配布時にその旨を伝えてください。
> * 使えるクラスと名前は、ゲームの `Sephiria_Data\Managed\Assembly-CSharp.dll` をILSpyやdnSpyで開けば全部確認できます。

## マルチプレイ

**Modを入れておくと、同じModを使う人同士でしか部屋一覧にお互いが見えません。**

ゲームには「この人がどのアドオンを入れているか」を部屋一覧で問い合わせる通路がありません。
ところがゲームはすでに**バージョン文字列一つで部屋を絞り込んでいます。** 部屋を作るとその値がSteamロビー情報に書かれ(`HandleCreated`)、部屋一覧は**バージョンが自分と違う部屋をそもそも描きません**(`HandleFound`)。コードで直接入る道もSteam招待も同じ値を見比べ、そこを抜けても接続認証(`HorayNetworkAuthenticator`)が拒否します。

そこでランタイムはバージョンの後ろに**有効にしたModの名前とバージョン**を付け足します。

```
1.2.3                              バニラ
1.2.3 +MM[mycharms v1.0.0]         Modを一つ入れている人
1.2.3 +MM[4#8f2c1a90]              長いときは個数と指紋に縮めます (絞り込む働きは同じです)
```

カスタムアイテムを知らない人が入ってきて見知らぬIDを受け取り、セーブが壊れることを最初から防ぐ仕組みです。

* **Modの一覧が正確に同じである必要があります。** 同じModでもバージョンが違うとアイテムの番号がずれることがあるため、一緒に遊べません。Modを読む順番は関係ありません。文字列は常に名前順に並べます。
* **Modを一つも有効にしていなければ何も付きません。** ランタイムだけ入れている人はバニラの人とそのまま遊べます。
* このロックは2.5.26から常にオンで、切ることはできません。古い `config.json` に残った `"lockMultiplayer": false` も無視します。
* バージョン文字列は部屋の絞り込み以外では画面表示とセーブの記録用の欄にしか使われず、その欄を読み返して見比べる場所はゲームにありません。**セーブには影響しません。**
* 同じ場所を触る別のアドオンと一緒に入れると印が複数付きます。そのときは**そのアドオンまで同じように揃えた人同士でしか**部屋が見えません。

## 配布

`配布用ファイルを作成` を押すと、受け取った人が展開するだけで済むzipができます。ゲームフォルダ基準のパス構造とインストール手順のテキストまで入ります。

| オプション | 内容 |
|---|---|
| **ランタイムを同梱** | 受け取った人がランタイムを別途入れる必要がなくなります |
| **単一パッケージで配布** | Mod構造を `mod.pak` ファイル一つにまとめます |
| **Modの暗号化** | フォルダを開いてそのままコピーされるのを防ぎます |

> まとめたModは ModMaker Runtime 0.4.0 以上でしか読めません。
> 暗号化は完全な保護ではありません。ゲームが読む必要がある以上、ランタイムは必ず解けます。

**自分で圧縮しないでください。** `AddOns` フォルダを丸ごと渡すと `testGiveItems` が入ったまま出て、`Mods\` の中の他人のModまで入り、キャッシュファイルが付いてきます。`配布用ファイルを作成` はこの3つを自動で処理します。

> **マルチプレイ**: 一緒に遊ぶ全員が同じModを入れる必要があります。アイテムのネットワークIDは `ModID:アイテム名` のハッシュで決まるので、同じModなら双方で一致します。

## トラブルシューティング

### Modがゲームに出てきません

ゲーム画面には何も表示されません。ログを見てください。

```
C:\Users\<ユーザー>\AppData\LocalLow\TEAMHORAY\Sephiria\Player.log
```

`ツール ▾` の `Player.log を開く` を押すと、そのフォルダがファイルを選択した状態で開きます。

正常ならこういう行が見えます。

```
[AddOnLoader] ✓ 'ModMaker Runtime' v2.5.26 by ModMaker
[ModMakerRuntime] Mod発見: My Mod v1.0.0 (アイテム3個, パッチ0件)
```

1行もなければランタイムが入っていません。`Preferences (設定)` の `ModMaker Runtime` から入れ直してください。
`[AddOnLoader]` はあるのに `[ModMakerRuntime]` がなければ、まだロビーかランに入っていません。

### 直した内容が反映されません

ゲームは数値を変えても再起動が要ります。エディタ側が疑わしいときはタイトルバーの `build` 時刻を見てください。古いコピーを動かしているかもしれません。

### 武器タブの欄が空です

武器リスト・打撃数・専用打撃・クロスボウ諸元はゲームが作る情報です。ランタイムを入れた状態でランに入ると作られます。ModMakerを新しい版に上げた直後にも同じ案内が出ることがあります。

### 武器の数値を直したのにゲーム内で変わりません

基本コンボを一切使わない武器種があります。カスタム武器で殴ると `Player.log` にどの値が使われたか残ります。

```
[ModMakerRuntime] 'MyMod/MyBlade': 基本1打を発射, データ 'Weapon_GreatSword_Attack1(M)-MM'
```

名前が `-MM` で終わっていればModMakerが直した値が使われたということで、そうでなければその武器が自前の打撃データを使ったということです。この記録が要らなければ `config.json` で `"logWeaponAttacks": false` にして切ってください。

### 作った武器が強化リストに出ません

金床は親の強化候補のうち3つだけをランダムで見せます。1段武器ごとに候補が8~10個あるので、一度で出ないのが普通です。ダイスで振り直すか、総合訓練場で確認してください。登録自体できているかは `Player.log` に残ります。

### ステータス一覧が短い、または「不明なステータスID」が出ます

`CRITICAL` のような一部のステータスはゲームを一度起動しないと一覧に入りません。ランに入ると全一覧ができ、エディタがそのコピーを保管します。一覧が不完全な間は、知らないIDだという理由で保存を止めることはしません。

### エディタでエラーウィンドウが出ました

作業内容はそのままで続けられます。詳しくは `%TEMP%\modmaker_error.log` に残ります。

## 制限事項

* 画像とフレームアニメーションは取り込み・差し替えができます。新しい攻撃判定・AI・魔法の動作は各フォームの対応範囲に限られ、それ以外はスクリプトが必要です。
* 武器の打撃数は変えられません。何回殴るかはモーションが決めます。
* クロスボウはクロスボウからしか強化されず、クロスボウ以外の武器にも強化されません。
* 武器タブのリスト・打撃数・専用打撃とバニラ事典は、ゲームを一度起動しないと埋まりません。
* 新しいステータスは登録できますが、ゲームが勝手に使うことはありません。発動制約やステータス変換で繋いで初めて意味を持ちます。
* 自分で作った発動制約のHP・MP・戦闘状態の条件は、置く場所のプレビューには反映されません。
* カスタム魔法は既存テンプレートの調整とバフ魔法までです。新しい詠唱挙動や投射物は作れません。
* 状態遷移とヒットボックスは複製元のコスチュームのものを使います。
* 攻撃方法と動きは複製元のモンスターのものを使います。
* ボスは仲間にできません。
* マルチプレイでカスタム仲間が正しく見えるには、両方が同じModを入れている必要があります。
* 開発中と表示された機能は、まだゲーム内での検証が終わっていません。
* カスタムスクリプトのビルドには .NET SDK が必要で、ゲームが更新されると再ビルドが要る場合があります。
* 効果テキストの `{VALUE}` のような自動置換はありません。数値は直接書いてください。
* コンテンツIDはセーブデータに記録されます。アイテム・武器・魔法の番号は自動で固定され、削除した番号も予約されます。Mod IDとゲームの `id-map.json` は保管し続けてください。
